# Project conventions

This file guides Claude Code sessions in this template. Keep it in sync with
the README when adding conventions.

## Stack

- Next.js 16 App Router + React 19 + TypeScript strict mode
- Tailwind CSS v4 (CSS-defined tokens in `app/globals.css`; no
  `tailwind.config.*`)
- shadcn/ui, neutral base color, light/dark via `next-themes`
- Supabase (`@supabase/ssr`) for auth, DB, storage
- Package manager: **pnpm** (see `packageManager` in `package.json`)

## Folder structure

```
app/                     App Router routes
  page.tsx               Public landing
  login/                 Magic-link sign-in (server action + page)
  auth/
    callback/route.ts    Finishes OAuth / magic-link exchange
    sign-out/route.ts    POST → signOut, redirect to /
  app/                   Signed-in area (Server Component layout guards it)
    layout.tsx           Checks getUser(), renders header + UserMenu
    page.tsx             Dashboard
    notes/               ← EXAMPLE FEATURE, safe to delete
      _example/          All example implementation
      page.tsx
components/
  ui/                    shadcn primitives (don't hand-edit; use the CLI)
  theme-provider.tsx     Wraps next-themes
  mode-toggle.tsx        Light/dark/system dropdown
lib/
  supabase/
    client.ts            Browser client (createBrowserClient)
    server.ts            Server Component / server action client (with cookies)
    middleware.ts        Session refresh + /app guard for proxy.ts
    service.ts           Service-role admin client (server-only; import 'server-only')
    types.ts             Generated by `pnpm db:types`; placeholder committed
supabase/
  config.toml            supabase init output
  migrations/            Timestamp-prefixed SQL files
proxy.ts                 Next.js 16 root proxy (was middleware.ts pre-v16)
```

## Where Supabase clients live

- **In a Server Component or server action** → `import { createClient } from
"@/lib/supabase/server"; const supabase = await createClient();`
  Uses `next/headers` cookies. Cookies can't be written from Server
  Components — the proxy handles session refresh.
- **In a Client Component** → `import { createClient } from
"@/lib/supabase/client";`
- **In `proxy.ts`** → use `updateSession` from `@/lib/supabase/middleware`.
- **In server-only admin code** (rare) → `import { createServiceClient } from
"@/lib/supabase/service";` — uses the service role key. Never import from a
  client component. The file uses `import "server-only"` to enforce this.

## Server actions vs client components

- Server actions live next to the route that uses them, typically in
  `actions.ts`. Mark files with `"use server";` at the top.
- Client components (`"use client";`) should be small — forms, interactivity,
  effects. Fetch data in Server Components and pass it down.
- Prefer server actions to route handlers for form submissions. Use route
  handlers only when you need a stable URL (webhooks, OAuth callbacks,
  `<form action="/foo">` POSTs from a static context, etc.).

## Adding a migration

```bash
# Use a UTC timestamp prefix so ordering is deterministic
touch "supabase/migrations/$(date -u +%Y%m%d%H%M%S)_add_widgets.sql"
```

Write the SQL, then:

```bash
pnpm db:push      # apply to the linked hosted project
pnpm db:types     # regenerate lib/supabase/types.ts
```

Every user-visible table should have `alter table … enable row level
security;` and per-user policies. See
`supabase/migrations/*_example_notes.sql` for the pattern.

## Adding a shadcn component

```bash
pnpm dlx shadcn@latest add <name>
```

Components land in `components/ui/`. Don't hand-edit them unless you have a
reason — re-running `add` will overwrite. If you need to customize, wrap or
compose in a new component under `components/`.

## Env vars

Every var lives in `.env.example` with an inline comment. Public vars are
prefixed `NEXT_PUBLIC_`. The service role key is server-only — never
reference it from a `"use client"` file or a component that isn't inside a
server-only boundary.

## Commands

Full list in the README. The four you'll use most:

- `pnpm dev` — dev server
- `pnpm db:push` — apply migrations to Supabase
- `pnpm db:types` — regenerate the Database type
- `pnpm lint && pnpm typecheck && pnpm build` — the CI trio
